# CONTRIBUTING.md

## Ревью кода: обязательные требования

**Стек проекта: Python + FastAPI + PostgreSQL + Docker.**

Настоящий документ — краткая выжимка из профиля ревьювера, адаптированная под стек. Он не заменяет полный профиль, но фиксирует **блокирующие** требования. Если код нарушает пункт — PR отклоняется без обсуждения. Если нарушение не описано явно — действует дух правил: **предсказуемость, отсутствие UB-эквивалентов, минимум тактов и аллокаций, осмысленный нейминг**.

---

## 0. Область применения

Правила действуют для **всего Python-кода** проекта (FastAPI-роуты, сервисы, репозитории, модели, миграции, тесты) и для **Docker/инфраструктурных** файлов. Специфика других языков из полного профиля применяется, если в проекте появляются C-расширения, Rust-биндинги или Go-сервисы.

Перед ревью определи зону риска: **UB-эквиваленты Python** (мутабельные дефолты, гонки потоков, `eval`), **hot path FastAPI** (сериализация, зависимости, ORM), **поведение под нагрузкой** (N+1, лишние аллокации, блокирующие вызовы в event loop).

## 1. Блокирующие дефекты (Hard No)

### 1.1. UB-эквиваленты Python

Любой паттерн, который ведёт к неопределённому/непредсказуемому поведению, **блокирует PR**.

- **Мутабельные дефолты**: `def parse(chunks=[]):` — состояние разделяется между вызовами. Fix: `def parse(chunks: list[bytes] | None = None): chunks = chunks or []`.
- **`eval`/`exec`** на внешних данных — дефект безопасности. Блокировать.
- **Гонки в потоках**: GIL не защищает составные операции (`counter += 1` из нескольких потоков). Дефект.
- **Гонки в `async`**: общий мутабельный стейт между корутинами без синхронизации; `asyncio.Lock` там, где нужен.
- **Блокирующие вызовы в event loop**: `requests`, `time.sleep`, синхронный драйвер БД, тяжёлый CPU-bound код прямо в `async def` — блокирует весь воркер. Fix: `run_in_executor` / `anyio.to_thread` / async-драйвер (`asyncpg`, `psycopg` в async-режиме).
- **Голый `except:` / `except Exception:` с проглатыванием** — скрывает ошибки, превращает дефект в «иногда работает». Требуется конкретный тип или логирование с re-raise.
- **Секреты в коде/логах** (пароли, токены, DSN с креденшелами) — блокировать.

### 1.2. Скрытый тип, скрывающий стоимость

- **Type hints обязательны в публичном API**: `def parse(x: bytes) -> Packet:`, а не `def parse(x):`.
- **Pydantic-модели** — с явными типами полей; `Any` в схеме запроса/ответа требует обоснования.
- **Возвращаемые типы репозиториев/сервисов** — явные (`list[User]`, `User | None`), не «что получилось из ORM».

## 2. Бюджет ветвлений и локальность

### 2.1. Глубина условных конструкций

Максимум **2 уровня** вложенных `if` / `match` внутри функции. Третий уровень — рефакторинг: early return, `guard`-паттерн, выделение функции, таблица переходов (`dict`-диспетчеризация вместо цепочки `if`).

Каждый `if` — ветвление; в hot path FastAPI-хендлера глубокая вложенность — удар по latency и читаемости.

### 2.2. Локальность и аллокации

- **ORM-запросы**: N+1 — блокирующий дефект. `selectinload`/`joinedload` для связей, `lazy="raise"` как дефолт для моделей, где N+1 недопустим.
- **Сериализация Pydantic** в hot path: не гонять `model_dump()`/`model_validate()` в цикле без нужды; использовать `model_dump(mode="json")` осознанно.
- **Массивы данных** — NumPy / `array` / `memoryview`, а не список списков.
- **Лишние копии списков** (`list(...)`, `+`, `sorted()` без нужды) — отказ в hot path.

## 3. Минимум бессмысленных тактов ЦП

Метрика ревью: **«Сколько тактов/аллокаций/запросов к БД потрачено впустую?»**

**FastAPI:**
- Зависимости (`Depends`) в hot path — без тяжёлой инициализации на каждый запрос; кэшировать через `lru_cache`/DI-скоуп.
- `async def` для I/O-bound, `def` для CPU-bound (FastAPI уведёт в threadpool); смешение без понимания — дефект.
- Middleware — минимальные; тяжёлая логика в middleware бьёт по всем роутам.

**SQLAlchemy / Postgres:**
- `SELECT *` через ORM без `load_only` — лишние колонки, лишний трафик.
- Запросы в цикле — N+1 или batch (`IN`, `executemany`).
- Транзакции — явные границы; долгие транзакции держат локи.
- Индексы под фактические `WHERE`/`ORDER BY` — отсутствие индекса на горячем запросе — дефект.
- `JSON`-поля для того, что фильтруется/джойнится — кандидат на нормализацию.

**Python:**
- Циклы на Python в hot path — NumPy / `array` / C-расширение.
- Лишние аллокации в цикле (конкатенация строк, `list.append` в гигантский список) — вынести.
- `time.sleep` / `requests` в `async` — блокировка loop (см. 1.1).

**Docker:**
- Образы — multi-stage, минимальный базовый (`python:slim`), без dev-зависимостей в runtime.
- `.dockerignore` — обязателен (`.venv`, `__pycache__`, `.git`, тесты).
- `COPY` только нужного; слой с зависимостями кэшируется отдельно от кода.
- Не `root` в runtime (пользователь без привилегий).
- Секреты — не в `ENV`/`ARG`/слое образа; только через секреты/переменные окружения.

## 4. Нейминг

Плохое имя — скрытая стоимость сопровождения и сигнал о непонимании типа. Нарушения ниже — **отклонить без обсуждения**.

### 4.1. Стиль Python

- **`snake_case`** для функций/переменных, **`PascalCase`** для классов, **`SCREAMING_SNAKE_CASE`** для констант. **PEP 8 — обязателен.**
- **Type hints обязательны** в публичном API (см. 1.2).
- **Pydantic-модели** — `PascalCase` (`UserCreate`, `OrderResponse`); поля — `snake_case`, совпадают с API-контрактом или явно алиасятся.
- **FastAPI-роуты** — глагол + существительное: `create_user`, `get_order`, `list_items`; без «шумных» `handle_`/`process_` без объекта.

### 4.2. Запрет лишних подчёркиваний и префиксов

- **Никаких trailing `_`** для «приватности» без причины. `int value_` / `self.count_` — отклонить, если нет коллизии с параметром.
- **Никаких leading `_`** для «приватных» полей, кроме осознанной коллизии; `__` (name mangling) — только где действительно нужно, не «на всякий случай».
- **Двойные подчёркивания `__foo`** — не использовать для «приватности» вне осознанного name mangling; в C-расширениях/FFI — зарезервировано реализацией.
- **`_` как имя** — только discard в распаковке; в остальных местах — бессмысленное имя, отклонить.
- **Венгерская нотация и префиксы типа** (`strName`, `arrItems`, `iCount`, `bFlag`) — отклонить: тип уже в аннотации.
- **Исключение**: префиксы, несущие **семантику**, а не тип (`g_` для глобалов, `k` для констант), — только если зафиксировано в style guide проекта.

### 4.3. Запрет «шумных» имён

- `data`, `info`, `obj`, `item`, `value`, `tmp`, `temp`, `foo`, `bar`, `baz` — отклонить, если имя не несёт смысла. `process(data)` — что за data? `process(packet: Packet)` — принять.
- `i`, `j`, `k` — только индексы циклов в пределах 3–5 строк; глубже или дольше — `row`, `col`, `byte_index`.
- `flag`, `status`, `result` без уточнения — отклонить; `parse_status`, `checksum_result` — принять.
- Аббревиатуры — только общепринятые (`id`, `url`, `http`, `cpu`, `db`, `api`). `usr`, `msg`, `buf`, `len`, `cnt`, `val` — отклонить в публичном API; в локальном скоупе до 3 строк — с оговоркой.

### 4.4. Согласованность

- **Один концепт — одно имя** во всём проекте. `buffer`/`buf`/`mem` в разных местах — отклонить.
- **Глаголы для функций**: `get_` / `set_` / `is_` / `has_` / `can_` / `parse_` / `compute_` / `validate_`. Функция `data()` без глагола — отклонить.
- **Существительные для типов** — единственное число (`User`, `Order`); коллекции — множественное (`users`, `handlers`).
- **Булевы**: `is_`, `has_`, `can_`, `should_`, `was_`. `bool ready;` — отклонить, `bool is_ready;` — принять.
- **Смешение `HTTPServer` и `HttpClient`** — отклонить; выбрать один стиль аббревиатур.

### 4.5. Длина и читаемость

- Имя должно быть **произносимо вслух**. `xq_cnt` — отклонить, `xq_count` — принять.
- Односимвольные имена — только счётчики циклов и координаты.
- Слишком длинные имена (> 40 символов) — сигнал о раздутой ответственности; требовать разбиения, а не сокращения.
- Транслит и русские слова в идентификаторах — отклонить.

## 5. Формат комментария ревью

Каждый комментарий содержит:

1. **Файл:строка**.
2. **Категория**: `[UB]`, `[BRANCH]`, `[CACHE]`, `[TYPE]`, `[CYCLE]`, `[NAME]`, `[MEM]`, `[DB]`, `[DOCKER]`.
3. **Проблема** — одно предложение, без воды.
4. **Исправление** — конкретный код или направление рефакторинга.

### Примеры

```
app/parsers.py:12 [UB] Мутабельный дефолт `def parse(chunks=[]):` — состояние разделяется между вызовами.
Fix: `def parse(chunks: list[bytes] | None = None): chunks = chunks or []`

app/routes/orders.py:44 [UB] Синхронный `requests.get` внутри `async def` — блокирует event loop.
Fix: `httpx.AsyncClient` или `await anyio.to_thread.run_sync(...)`.

app/repositories/users.py:88 [DB] N+1: `user.orders` в цикле без `selectinload`.
Fix: `select(User).options(selectinload(User.orders))`.

app/routes/items.py:31 [TYPE] `def get_items():` без аннотаций в публичном API.
Fix: `def get_items(limit: int = 100) -> list[ItemResponse]:`.

app/services/billing.py:57 [NAME] `process(data)` — имя не несёт смысла.
Fix: `process_invoice(invoice: Invoice)`.

app/services/billing.py:63 [NAME] `tmp` и `value` без уточнения.
Fix: `pending_total`, `discount_amount`.

app/models.py:22 [DB] `JSON`-поле `metadata` фильтруется в горячем запросе — кандидат на нормализацию.
Fix: вынести фильтруемые ключи в колонки + индекс.

Dockerfile:14 [DOCKER] `COPY . .` без `.dockerignore` — в образ попадают `.venv`, `.git`, тесты.
Fix: `.dockerignore` + `COPY pyproject.toml uv.lock ./` отдельным слоем.

Dockerfile:21 [DOCKER] Запуск от `root` в runtime.
Fix: `USER app` после `COPY` и `chown`.
```

## 6. Тон

**Сухой. Без похвалы. Без «можно было бы».**

- Нарушение правила — «Отклонить».
- UB-эквивалент / блокировка loop / N+1 — «Блокирующий дефект».
- Оптимизация возможна, но не обязательна — «Требуется обоснование в комментарии, иначе отклонить».

---

## Итоговое правило

> **Имя, которое не сообщает ничего сверх типа, — это имя, которого не должно быть.**
> Тип уже сказан в аннотации. Имя должно сказать **роль, смысл, единицу измерения, инвариант** — и ничего больше.

> **Код, который полагается на удачу рантайма, GIL, ORM или GC, — это не код, а лотерея.**
> Ревьювер не играет в лотерею — ни в Python, ни в SQL, ни в Docker.
